این راهنما **یک فروشگاه مستقل با یک ربات تلگرام** را با سرویس‌های Docker همین پروژه راه‌اندازی می‌کند. با مراحل ۱ تا ۶، پروژه روی سیستم شما اجرا می‌شود؛ برای استفاده داخل تلگرام و ساخت اولین محصول، مراحل ۷ تا ۹ را هم انجام دهید.

دستورها را در پوشه پروژه اجرا کنید، مگر جایی که محل دیگری مشخص شده باشد. روی سرور، دستورها در نشست SSH اجرا می‌شوند. در ویندوز، از ترمینال لینوکس WSL 2 با اتصال فعال به Docker Desktop استفاده کنید.

| هدف شما چیست؟ | از کدام مسیر بروید؟ |
|---|---|
| بررسی پنل روی کامپیوتر شخصی | مراحل ۱ تا ۶؛ دامنه عمومی لازم نیست. |
| استفاده از فروشگاه داخل تلگرام | مراحل ۱ تا ۹؛ در مرحله ۷ یک URL عمومی HTTPS آماده کنید. |

<a name="step-1"></a>

## ۱. 🧰 آماده‌کردن سیستم یا سرور

به این موارد نیاز دارید:

- **Git** برای دریافت و به‌روزرسانی سورس.
- **Docker Engine همراه Compose نسخه ۲** روی لینوکس، یا **Docker Desktop** روی مک و ویندوز. پیش از ادامه، Docker Desktop باید اجرا شده باشد.
- حساب تلگرام و توکن ربات از [BotFather](https://t.me/BotFather).
- دسترسی اینترنت برای دریافت imageها، وابستگی‌های ساخت و ارتباط با API تلگرام.
- برای نصب عمومی: سرور با IP عمومی و دو دامنه یا زیردامنه تحت اختیار شما. در مثال‌ها از `shop.example.com` و `admin.example.com` استفاده شده است؛ هر دو را با نشانی‌های خودتان عوض کنید.

برای شروع ساخت روی سرور، ۲ هسته پردازنده و ۴ گیگابایت RAM در نظر بگیرید. فضای دیسک به فایل‌های محصولات و بارگذاری‌ها بستگی دارد؛ برای ساخت و پشتیبان‌ها نیز فضا لازم است.

اگر Docker نصب نیست، راهنمای رسمی [اوبونتو](https://docs.docker.com/engine/install/ubuntu/)، [مک](https://docs.docker.com/desktop/setup/install/mac-install/) یا [ویندوز](https://docs.docker.com/desktop/setup/install/windows-install/) را دنبال کنید. در روش Docker، نیازی به نصب جداگانه Go، Node.js، PostgreSQL یا MinIO روی میزبان ندارید.

ابزارها را بررسی کنید:

```sh
git --version
docker --version
docker compose version
docker info
```

> ✅ **نتیجه مورد انتظار:** دستورهای نسخه بدون خطا اجرا شوند و `docker info` به موتور Docker وصل شود. اگر این دستور خطا دارد، ابتدا اجرای Docker یا دسترسی کاربر به آن را اصلاح کنید.

<a name="step-2"></a>

## ۲. 🤖 ساخت ربات تلگرام

1. [@BotFather رسمی](https://t.me/BotFather) را باز کنید.
2. دستور `/newbot` را بفرستید و نام نمایشی و نام کاربری ربات را طبق راهنمای آن انتخاب کنید.
3. توکن ربات را نگه دارید؛ در مرحله ۴ آن را در `BOT_TOKEN` قرار می‌دهید.

استفاده از ربات موجود هم ممکن است. پیش از اجرای این پروژه، نصب یا پردازش دیگری را که با همان توکن رویدادهای تلگرام را دریافت می‌کند، متوقف کنید. روش پیش‌فرض **polling** است: ربات خودش از تلگرام رویداد می‌گیرد و برای دریافت آن‌ها به نشانی webhook عمومی نیاز ندارد.

<a name="step-3"></a>

## ۳. 📥 دریافت سورس و ساخت فایل `.env`

```sh
git clone --branch main https://github.com/amirmalek0/telegram-marketplace.git
cd telegram-marketplace
cp .env.example .env
```

اکنون باید فایل‌های `.env` و `docker-compose.yml` و پوشه‌های `core/`، `miniapp/` و `backoffice/` را ببینید. فایل `.env` تنظیمات خصوصی نصب شماست؛ `.env.example` فقط الگوست.

> 🔐 **کپی الگو فقط برای نصب جدید است.** تکرار این دستور روی `.env` موجود، تنظیمات و رمزهای فعلی را جایگزین می‌کند. فایل `.env` را commit نکنید و محتوای آن را در اختیار دیگران نگذارید.

<a name="step-4"></a>

## ۴. 🔐 تنظیم توکن، رمزها و اطلاعات پایه

فایل `.env` را با ویرایشگر متن باز کنید. پیش از اولین اجرا، این مقادیر را تغییر دهید:

| متغیر | چه مقداری وارد شود؟ |
|---|---|
| `BOT_TOKEN` | توکن کامل دریافتی از BotFather. این نصب باید در تمام بخش‌ها از همین ربات استفاده کند. |
| `JWT_SECRET` | کلید تصادفی امضای نشست مدیران؛ خروجی ۶۴ کاراکتری دستور زیر مناسب است. |
| `ADMIN_SEED_USERNAME` | نام کاربری مدیر اولیه؛ برای مثال `admin`. |
| `ADMIN_SEED_PASSWORD` | رمز اختصاصی مدیر اولیه. |
| `POSTGRES_PASSWORD` | رمز اختصاصی پایگاه داده همراه پروژه. |
| `MINIO_SECRET_KEY` | رمز یا کلید اختصاصی ذخیره‌ساز همراه پروژه. |

برای ساخت یک مقدار تصادفی:

```sh
openssl rand -hex 32
```

این دستور را برای هر رمز یا کلید، جداگانه اجرا و خروجی متفاوت را در فیلد مربوط قرار دهید. خروجی hex کاراکتر خاص ندارد و در فایل محیط و نشانی اتصال پایگاه داده، به escape نیاز پیدا نمی‌کند. عبارت‌های نمونه زیر را عیناً به‌عنوان رمز استفاده نکنید:

```dotenv
BOT_TOKEN=PASTE_YOUR_BOTFATHER_TOKEN
JWT_SECRET=PASTE_A_RANDOM_HEX_VALUE
ADMIN_SEED_USERNAME=admin
ADMIN_SEED_PASSWORD=PASTE_A_DIFFERENT_RANDOM_HEX_VALUE
POSTGRES_PASSWORD=PASTE_ANOTHER_RANDOM_HEX_VALUE
MINIO_SECRET_KEY=PASTE_ANOTHER_DIFFERENT_RANDOM_HEX_VALUE
```

برای اجرای اولیه با Docker، بقیه تنظیمات الگو را نگه دارید. موارد زیر معمولاً ابهام ایجاد می‌کنند:

| تنظیم | رفتار آن در این راهنما |
|---|---|
| `DOCKER_DATABASE_URL` | خالی بماند. Compose نشانی داخلی را با `POSTGRES_USER`، `POSTGRES_PASSWORD` و `POSTGRES_DB` می‌سازد. |
| `DATABASE_URL` | برای اجرای مستقیم برنامه Go روی میزبان است و اتصال Docker را جایگزین نمی‌کند. اگر بعداً Go را خارج Docker اجرا کردید، رمز آن را با PostgreSQL هماهنگ کنید. |
| `WEBHOOK_URL` | برای polling خالی یا تعریف‌نشده بماند. راه‌اندازی HTTPS پایین نیز به webhook نیاز ندارد. |
| `HOST_BIND` | روی `127.0.0.1` بماند. پورت‌های پایگاه داده، ذخیره‌ساز، API و فرانت‌اند محلی می‌مانند؛ درگاه HTTPS سایت‌ها را عمومی می‌کند. |
| `MINIAPP_PUBLIC_URL` | برای اجرای محلی، `http://localhost:3000` بماند. در مرحله ۷ به نشانی عمومی مینی‌اپ تغییر می‌کند؛ پیش‌نمایش ویرایشگر پنل از آن استفاده می‌کند. |
| `VITE_API_BASE_URL` | همان `/api/v1` بماند. فرانت‌اندهای Docker درخواست‌ها را از مبدأ خودشان به API هدایت می‌کنند. |
| `STORAGE_ENDPOINT` و نشانی باکت‌ها | مقادیر الگو را نگه دارید. Compose داخل شبکه از `minio:9000` و برای مرورگر از مسیر `/storage/` استفاده می‌کند. |

برای این نصب، متغیرهای اختیاری `MINIAPP_API_URL` و `BACKOFFICE_API_URL` را تنظیم نکنید. مرورگر مینی‌اپ عمومی HTTPS نباید درخواست‌ها را به `http://localhost:8080` بفرستد.

بدون چاپ‌کردن رمزهای نهایی، صحت تنظیم Compose را بررسی کنید:

```sh
docker compose config --quiet
```

> ✅ **نتیجه مورد انتظار:** خطای تنظیمات نمایش داده نشود. این مرحله صحت توکن در تلگرام را بررسی نمی‌کند؛ فقط ساختار تنظیمات Compose را کنترل می‌کند.

<a name="step-5"></a>

## ۵. 🚀 ساخت و اجرای سرویس‌ها

```sh
docker compose up -d --build
docker compose ps
curl --fail http://localhost:8080/health
```

ساخت اول به دریافت وابستگی‌ها نیاز دارد و ممکن است چند دقیقه طول بکشد. گزینه `-d` باعث می‌شود سرویس‌ها در پس‌زمینه فعال بمانند.

> ✅ **نتیجه مورد انتظار:** سرویس‌های `postgres`، `minio`، `api`، `bot`، `miniapp` و `backoffice` در حال اجرا باشند؛ بررسی سلامت زیرساخت‌ها به حالت healthy برسد و API پاسخ `{"status":"ok"}` بدهد. جدول‌های پایگاه داده، باکت‌های ذخیره‌سازی و مدیر اولیه خودکار ایجاد می‌شوند؛ واردکردن SQL یا ساخت دستی باکت لازم نیست.

اگر سرویسی متوقف می‌شود یا مرتب restart دارد، پیش از ادامه گزارش آن را بخوانید:

```sh
docker compose logs --tail=100 api bot
docker compose logs --tail=100 postgres minio
```

در زمان اجرای این سرویس‌ها، نسخه دیگری از همان توکن ربات را اجرا نکنید.

<a name="step-6"></a>

## ۶. 🖥️ ورود به پنل مدیریت

اگر روی کامپیوتر خودتان نصب کرده‌اید:

| بخش | نشانی پیش‌فرض | کاربرد |
|---|---|---|
| پنل مدیریت | http://localhost:3001 | ورود و مدیریت فروشگاه. |
| مینی‌اپ | http://localhost:3000 | بررسی بازشدن فرانت‌اند؛ استفاده احرازشده مشتری از داخل تلگرام انجام می‌شود. |
| سلامت API | http://localhost:8080/health | بررسی پاسخ‌گویی API. |
| کنسول MinIO | http://localhost:9001 | مدیریت اختیاری ذخیره‌ساز با `MINIO_ACCESS_KEY` و `MINIO_SECRET_KEY`. |

با `ADMIN_SEED_USERNAME` و `ADMIN_SEED_PASSWORD` ذخیره‌شده در `.env` وارد شوید. این مقادیر **فقط هنگام اولین آماده‌سازی پایگاه داده** مدیر را می‌سازند. تغییر آن‌ها در اجرای بعدی، رمز مدیر موجود را عوض نمی‌کند؛ برای تغییر رمز از گزینه مربوط در پنل استفاده کنید.

> 💡 **اگر روی سرور نصب می‌کنید، localhost به سرور اشاره دارد، نه لپ‌تاپ شما.** مرحله ۷ را انجام دهید و سپس دامنه عمومی پنل را باز کنید. اگر پیش از آماده‌شدن DNS به پنل نیاز دارید، این دستور را روی کامپیوتر خودتان اجرا کنید و حساب SSH و IP را عوض کنید:

```sh
ssh -N -L 3000:127.0.0.1:3000 -L 3001:127.0.0.1:3001 deploy@YOUR_SERVER_IP
```

نشست SSH را باز نگه دارید و در مرورگر کامپیوتر خود به `http://localhost:3001` بروید. این روش، پنل و مینی‌اپ را بدون عمومی‌کردن پورت‌ها به کامپیوتر شما هدایت می‌کند.

<a name="step-7"></a>

## ۷. 🌐 اتصال دامنه و فعال‌کردن HTTPS

برای استفاده مشتری داخل تلگرام، مینی‌اپ باید نشانی HTTPS قابل دسترس داشته باشد. پروژه یک درگاه اختیاری Caddy دارد که گواهی هر دو فرانت‌اند را دریافت و تمدید می‌کند.

1. در سرویس DNS، برای هر زیردامنه یک **رکورد A** به IP عمومی نسخه ۴ سرور بسازید. رکورد AAAA فقط وقتی تنظیم شود که همان سرور IPv6 عمومی فعال و قابل دسترس دارد.
2. در فایروال سرور و ارائه‌دهنده، ورودی TCP پورت‌های **۸۰ و ۴۴۳** را باز کنید و دسترسی SSH را نگه دارید. این دو پورت باید آزاد باشند؛ اگر وب‌سرور دیگری از آن‌ها استفاده می‌کند، همان reverse proxy را تنظیم کنید، نه یک درگاه دوم روی همان پورت‌ها.
3. این مقادیر را در `.env` با دامنه‌های واقعی خودتان جایگزین کنید:

```dotenv
MINIAPP_DOMAIN=shop.example.com
BACKOFFICE_DOMAIN=admin.example.com
MINIAPP_PUBLIC_URL=https://shop.example.com
CORS_ALLOWED_ORIGINS=https://shop.example.com,https://admin.example.com
```

`MINIAPP_DOMAIN` و `BACKOFFICE_DOMAIN` فقط نام میزبان هستند؛ `https://` یا مسیر ندارند. مقدار `MINIAPP_PUBLIC_URL` یک URL کامل است. در CORS، مبدأها را بدون مسیر و اسلش انتهایی وارد کنید. دامنه عمومی جدا برای API و ذخیره‌ساز لازم نیست.

4. درگاه HTTPS را همراه ساخت مجدد فرانت‌اندها اجرا کنید تا نشانی عمومی پیش‌نمایش در پنل اعمال شود:

```sh
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

5. نشانی‌های `https://shop.example.com` و `https://admin.example.com` را باز کنید. هر دو باید با گواهی معتبر نمایش داده شوند. اگر دریافت گواهی ناموفق بود، DNS و گزارش درگاه را بررسی کنید:

```sh
docker compose -f docker-compose.yml -f docker-compose.https.yml logs --tail=100 gateway
```

تغییر فایل `.env` به‌تنهایی سرویس در حال اجرا را عوض نمی‌کند. پس از تغییر نشانی‌ها، دستور `up -d --build` را تکرار کنید؛ `MINIAPP_PUBLIC_URL` هنگام ساخت داخل فرانت‌اند مدیریت قرار می‌گیرد.

برای آزمایش محلی، یک تونل HTTPS می‌تواند به **پورت ۳۰۰۰ مینی‌اپ** وصل شود. URL عمومی تونل را در BotFather و `MINIAPP_PUBLIC_URL` قرار دهید و فرانت‌اند مدیریت را دوباره بسازید. با تغییر URL موقت، این دو تنظیم هم باید عوض شوند. تونل، جایگزین درگاه بالاست و وابستگی اجباری پروژه نیست.

<a name="step-8"></a>

## ۸. ✈️ اتصال مینی‌اپ به ربات

1. در BotFather دستور `/setmenubutton` را بفرستید و ربات را انتخاب کنید.
2. URL مینی‌اپ، مثلاً `https://shop.example.com`، را وارد و متنی مثل «فروشگاه» برای دکمه انتخاب کنید.
3. برای نمایش دکمه اجرا در پروفایل ربات، می‌توانید **Main Mini App** را هم در BotFather با همان نشانی تنظیم کنید.
4. گفت‌وگوی خصوصی ربات را باز کنید، `/start` بفرستید و فروشگاه را از دکمه منوی آن باز کنید.

> ✅ **نتیجه مورد انتظار:** مینی‌اپ داخل تلگرام باز شود و صفحات مشتری بتوانند کاربر را احراز هویت کنند. مرورگر معمولی اطلاعات `initData` تلگرام را تأمین نمی‌کند؛ بازکردن URL در آن، آزمایش معتبر ورود مشتری نیست.

متغیر `MINIAPP_PUBLIC_URL` برای پیش‌نمایش پنل است و BotFather را خودکار تنظیم نمی‌کند. حتی اگر Main Mini App را فعال کرده‌اید، Menu Button را هم تنظیم کنید؛ ربات برای دکمه ورود به فروشگاه از URL آن استفاده می‌کند. [راهنمای رسمی تنظیم مینی‌اپ تلگرام](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button) را نیز می‌توانید ببینید.

<a name="step-9"></a>

## ۹. ✅ آماده‌سازی فروشگاه و آزمایش یک خرید کامل

در پنل فارسی:

1. از **دسته‌بندی‌ها** یک دسته فعال با عنوان، آیکون و ترتیب نمایش بسازید.
2. از **محصولات ← فایل** یک فایل کوچک بارگذاری کنید. سپس یک محصول بسازید، دسته را انتخاب کنید، روش تحویل را فایل بگذارید و فایل بارگذاری‌شده را متصل کنید. تصویر محصول به‌تنهایی منبع تحویل نیست.
3. از **پرداخت‌ها ← تنظیمات پرداخت** روش‌های دلخواه و نحوه نمایش قیمت را تنظیم و قیمت‌های محصول را وارد کنید. برای کارت‌به‌کارت، کارت مقصد را هم در **پرداخت‌ها ← کارت‌به‌کارت** تعریف کنید.
4. برای آزمایش بدون پرداخت واقعی، از **تنظیمات عمومی ← حالت سراسری پرداخت‌ها** آگاهانه حالت آزمایشی را فعال کنید. این حالت برای خرید محصول، VIP و شارژ کیف پول است؛ شبیه‌سازی خود برنامه است، نه sandbox جداگانه تلگرام. خرید موفق شبیه‌سازی‌شده، سفارش، تحویل، موجودی و دسترسی VIP فروشگاه را واقعاً تغییر می‌دهد. کارت‌به‌کارت آزمایشی هم بررسی مدیر می‌خواهد.
5. از تلگرام محصول را بخرید؛ سفارش و پرداخت را در پنل و دسترسی و دانلود را در حساب مشتری بررسی کنید. در کارت‌به‌کارت، بررسی کنید تحویل پیش از تأیید مدیر انجام نشود.
6. پیش از پذیرش پرداخت مشتریان، حالت را به پرداخت واقعی برگردانید. بسته‌های کیف پول، پلن‌های VIP، کوپن‌ها، الزام شماره، پاداش دعوت و پیام‌های ربات را متناسب با فروشگاه تنظیم کنید.

برای عرضه محصولات دیجیتال داخل تلگرام، پیش از انتخاب روش‌های پرداخت، [الزامات رسمی پرداخت Stars](https://core.telegram.org/bots/payments-stars) را بررسی کنید.

<details>
<summary><strong>✅ فهرست بررسی پیش از شروع فروش</strong></summary>

- [ ] هر دو دامنه عمومی با HTTPS معتبر باز می‌شوند.
- [ ] ورود مدیر و بازشدن مینی‌اپ از منوی ربات موفق است.
- [ ] خرید آزمایشی، سفارش و دسترسی تحویل مورد انتظار را ایجاد می‌کند.
- [ ] اگر کارت‌به‌کارت فعال است، تحویل تا تأیید مدیر منتظر می‌ماند.

<a name="operations"></a>

## 🗃️ اجرا، توقف، به‌روزرسانی و نگهداری داده‌ها

| کار | دستور یا اقدام |
|---|---|
| مشاهده سرویس‌ها | `docker compose ps` |
| مشاهده زنده گزارش API و ربات | `docker compose logs -f --tail=100 api bot`؛ با Ctrl+C فقط مشاهده گزارش متوقف می‌شود، نه سرویس‌ها. |
| توقف نصب محلی | `docker compose down` |
| اجرای مجدد نصب محلی | `docker compose up -d` |
| به‌روزرسانی سورس | ابتدا پشتیبان بگیرید، `git pull --ff-only` را اجرا و سپس دستور `up -d --build` مناسب نصب خود را تکرار کنید. |

در نصب HTTPS، برای دستورهای اجرا، توقف و به‌روزرسانی کل پروژه، هر دو گزینه **`-f docker-compose.yml -f docker-compose.https.yml`** را نگه دارید تا درگاه هم در فرمان قرار گیرد. تغییر تنظیمات زمان ساخت فرانت‌اند به `--build` نیاز دارد؛ دستور `docker compose restart` فایل `.env` را دوباره اعمال نمی‌کند.

داده‌های ماندگار در volumeهای Docker هستند: `pgdata` برای PostgreSQL و `miniodata` برای فایل‌ها و تصاویر. گواهی‌های HTTPS در `caddy_data` و `caddy_config` قرار می‌گیرند. نسخه خصوصی `.env` را هم همراه اطلاعات پشتیبان نگه دارید.

پیش از به‌روزرسانی یا انتقال سرور، از **هر دو PostgreSQL و MinIO** پشتیبان بگیرید. نمونه تهیه خروجی پایگاه داده:

```sh
mkdir -p ../telegram-marketplace-backups
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > ../telegram-marketplace-backups/database.dump
```

اجرای دوباره این دستور، فایل پشتیبان هم‌نام را جایگزین می‌کند. این خروجی شامل فایل‌های object storage نیست؛ برای MinIO نیز پشتیبان جدا یا snapshot volume تهیه کنید. هنگام تهیه snapshotهای هماهنگ، نوشتن داده را متوقف و امکان بازیابی را پیش از اتکا به پشتیبان بررسی کنید. دستور `docker compose down` volumeها را نگه می‌دارد؛ **`docker compose down -v` داده‌های فروشگاه را حذف می‌کند**.

تغییر رمزهای PostgreSQL یا MinIO در `.env`، به‌تنهایی راهنمای تغییر امن اطلاعات ورود نصب موجود نیست. به‌طور مشخص، رمز اولیه PostgreSQL هنگام ساخت اولین پوشه داده اعمال می‌شود؛ تغییر فایل محیط، رمز همان حساب پایگاه داده را عوض نمی‌کند.

ابزارهای اختیاری پایگاه داده در اجرای عادی فعال نیستند:

```sh
docker compose --profile tools up -d pgadmin dbeaver
```

این ابزارها به‌صورت محلی روی پورت‌های ۵۰۵۰ و ۸۹۷۸ در دسترس‌اند. اطلاعات پیش‌فرض آن‌ها برای ابزار محلی است؛ پیش از دادن دسترسی به دیگران تغییرشان دهید. برای مدیریت روزانه فروشگاه از پنل خود پروژه استفاده کنید.

<a name="troubleshooting"></a>

## 🛠️ رفع اشکال

| نشانه | بررسی و اقدام بعدی |
|---|---|
| اتصال به Docker برقرار نمی‌شود | Docker Desktop یا سرویس Docker را اجرا کنید؛ ابتدا `docker info` باید موفق باشد. |
| خطای `port is already allocated` | پورت میزبان مربوط را در `.env` تغییر دهید: `API_PORT`، `BOT_PORT`، `MINIAPP_PORT`، `BACKOFFICE_PORT`، `POSTGRES_PORT`، `MINIO_PORT` یا `MINIO_CONSOLE_PORT`. سپس `up -d --build` را اجرا کنید. با تغییر پورت فرانت‌اند، نشانی‌ها و CORS را هم هماهنگ کنید؛ پورت داخلی Docker عوض نمی‌شود. |
| خطای تلگرام `401` در ربات | `BOT_TOKEN` را با BotFather بررسی و کانتینر ربات را با `docker compose up -d bot` دوباره ایجاد کنید. |
| خطای تلگرام `409` در ربات | پردازش دیگری را که همان توکن را مصرف می‌کند متوقف کنید؛ فقط یک دریافت‌کننده polling فعال باشد. |
| خطای `502 Bad Gateway` در پنل یا API | وضعیت سرویس‌ها و گزارش API را بررسی کنید؛ ممکن است فرانت‌اند فعال باشد ولی API هنوز بالا نیامده یا به PostgreSQL و MinIO وصل نشود. |
| اطلاعات مدیر پذیرفته نمی‌شود | اطلاعات اولین آماده‌سازی را وارد کنید؛ تغییر جدید مقادیر seed رمز قبلی را عوض نمی‌کند. مطمئن شوید پنل همان نصب را باز کرده‌اید. |
| API مینی‌اپ `401` می‌دهد یا کاربر ثبت نمی‌شود | از داخل همان ربات در تلگرام باز کنید و تطابق توکن ربات و نشانی عمومی با این نصب را بررسی کنید. |
| API اشتراک‌گذاری شماره می‌خواهد | اگر دریافت شماره اجباری است، شماره خودتان را از طریق ربات به اشتراک بگذارید؛ محدودیت در بک‌اند هم اعمال می‌شود. |
| پیش‌نمایش پنل خالی است یا localhost را باز می‌کند | `MINIAPP_PUBLIC_URL` را اصلاح و backoffice را دوباره بسازید. مرورگر مدیر باید به نشانی مینی‌اپ دسترسی داشته باشد. |
| صفحه HTTPS به `http://localhost:8080` درخواست می‌زند | نشانی API فرانت‌اند را روی `/api/v1` نگه دارید، override مطلق را حذف و فرانت‌اند را دوباره بسازید. |
| گواهی HTTPS صادر نمی‌شود | رکوردهای A/AAAA هر دو دامنه، ورودی ۸۰ و ۴۴۳، تداخل پورت و گزارش gateway را بررسی کنید. |
| تصویر یا فایل باز نمی‌شود | گزارش MinIO و API و اطلاعات ورود ذخیره‌ساز را بررسی کنید. برای مشتری از مسیر `/storage/` استفاده شود، نه آدرس داخلی `minio:9000`. |

<a name="architecture"></a>

## 🏗️ معماری و نقشه فنی

<div dir="ltr">

```text
Customer in Telegram → miniapp nginx → /api/ → Go API → PostgreSQL
                               └──→ /storage/ → MinIO (signed assets)
Admin browser         → backoffice nginx → the same API and storage
Telegram updates      → Go bot → payment/phone/referral services
Public HTTPS domains  → Caddy → the two frontend nginx services
```

</div>

| مسیر یا سرویس | مسئولیت |
|---|---|
| `miniapp/` | رابط مشتری با React، TypeScript و Vite. اطلاعات امضاشده `initData` از تلگرام دریافت و در بک‌اند اعتبارسنجی می‌شود. |
| `backoffice/` | پنل فارسی با React و TypeScript؛ احراز هویت مدیران با نشست JWT. |
| `core/cmd/api` و `core/cmd/bot` | نقطه‌های ورود جدا برای HTTP API و دریافت‌کننده رویدادهای تلگرام. |
| `core/internal/core/` | ماژول‌های کاتالوگ، مالی، عضویت، پشتیبانی، تنظیمات و پیام‌های ربات. |
| `core/internal/app/` | تنظیمات، اتصال وابستگی‌ها، middleware، مسیریابی و آماده‌سازی پایگاه داده. |
| `core/internal/platform/` و `core/pkg/` | ارتباط با تلگرام، ذخیره‌ساز و سایر adapterها و کد مشترک زیرساختی. |
| `deploy/Caddyfile` | مسیریابی اختیاری HTTPS؛ پایگاه داده و ذخیره‌ساز به دامنه عمومی جدا نیاز ندارند. |

یک ماژول معمول بک‌اند این مسیر را دارد: <span dir="ltr">router → handler/DTO → service → repository → PostgreSQL</span>. handler ورودی را می‌خواند؛ service قواعد خرید و دسترسی را اعمال می‌کند؛ repository مسئول ذخیره و بازیابی است. SQL در فایل‌های query کنار repository قرار دارد. مهاجرت‌های پایگاه داده هنگام شروع و با قفل مشترک اجرا می‌شوند.

ربات به‌صورت پیش‌فرض با polling رویداد می‌گیرد. تأیید Stars یا تأیید مدیر برای کارت‌به‌کارت، خرید را تسویه می‌کند؛ پردازشگرهای تحویل، محتوای تنظیم‌شده را در اختیار خریدار می‌گذارند و کارهای پشتیبانی‌شده سرویس بیرونی را بازآزمایی می‌کنند. PostgreSQL سفارش‌ها، دسترسی‌ها و موجودی‌ها را نگه می‌دارد؛ MinIO محل فایل‌ها، رسیدها و تصاویر است. محتوای خصوصی از مسیر دارای کنترل دسترسی ارائه می‌شود، نه لینک آزاد فایل محصول.

### توسعه اختیاری فرانت‌اند

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

این روش Vite را اجرا و پوشه‌های `src/` و `public/` فرانت‌اند را برای بارگذاری زنده متصل می‌کند؛ پورت‌ها همان پورت‌های قبلی‌اند. برای Go بارگذاری زنده فعال نمی‌کند. از این فایل برای توسعه و از Compose عادی یا HTTPS برای استقرار استفاده کنید.
